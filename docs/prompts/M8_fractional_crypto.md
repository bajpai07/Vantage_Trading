## 1. Goal
Let a user trade crypto (BTC-USD, ETH-USD, SOL-USD, XRP-USD, DOGE-USD, and the other seeded pairs) with **fractional quantities** (up to 8 decimals) using **market orders**, 24/7, on the simulated feed, **without weakening any financial guarantee** that M1–M5 proved. Stocks and ETFs stay whole-share (their instrument `qty_step` is 1). **No limit/stop orders, no reservations, no order book (that is M8b).**

This is the riskiest change since M4a because quantities stop being integers. The old exactness argument (D-52: whole shares × tick prices are exact, zero-tolerance reconcile) no longer holds by itself, so this phase **restores exactness by construction** (D-84 below). Treat every invariant as non-negotiable: cash never negative, shares never oversold, ledger balanced per currency, position cost equals the sum of lots **exactly**, idempotent replay, atomic, concurrency-safe.

## 3. Decisions (record as D-84… `APPROVED by founder (M8)` unless you object with a reason)
- **D-84 Exact cost basis by construction.** Add `position_lots.cost_remaining numeric(38,8)` (total cost basis of the **remaining** quantity, 8 dp, NOT NULL, backfilled in the migration as `qty_open × cost_local_per_unit` for existing rows, which is exact for whole-share lots). The invariant becomes: **`POSITION_COST` ledger balance = Σ `cost_remaining` over open lots, exactly, always.** `cost_local_per_unit` stays as the informational per-unit cost at purchase. On a buy: `cost_remaining = C = round8(qty × fillPrice)` (the same number posted to `POSITION_COST`). On a sell that consumes `q` of a lot with `qty_open = Q` and `cost_remaining = R`: if `q = Q` the consumed cost is **exactly `R`** (by subtraction); otherwise consumed cost `= round8(R × q / Q)` (HALF_EVEN), and `cost_remaining` becomes `R − consumed`. The consumed costs summed over the sell are the basis `B` posted to the ledger. Position `avg_cost_local = Σ cost_remaining / Σ qty_open` (8 dp). The M4a `position_lots` update trigger must now allow `qty_open`, `cost_remaining` and `closed_at` to change and nothing else; the deferred I4 trigger additionally checks `cost_remaining ≥ 0`, `cost_remaining = 0` iff `qty_open = 0`, and (new) that for every account/instrument the position's cached cost equals Σ lot `cost_remaining` if such a cache exists (otherwise reconcile checks it). `reconcileAccount` compares with **zero tolerance** as before, now using `cost_remaining`.
- **D-85 Fractional quantities.** Order quantity is a decimal string with at most 8 decimals, validated **server-side** against the instrument's `qty_step`, `min_qty` and a documented `max_qty` (existing `QTY_STEP_VIOLATION` / `QTY_BELOW_MIN` rejects stay; add `QTY_ABOVE_MAX` only if the spec has no equivalent). Stocks/ETFs have `qty_step = 1`, so a fractional stock quantity is `QTY_STEP_VIOLATION`. The contract changes from "positive integer string" to "positive decimal string, ≤ 8 dp" and the browser never does arithmetic on it. `positions.qty`, `qty_open`, `filled_qty`, `executions.qty` already use 8-dp decimals; verify the column types and any CHECKs; fix any place that assumed integers (queries, JSON, number parsing, lint rules).
- **D-86 Amends TRADING_ENGINE §1 / D5 (whole shares in the MVP).** Whole-share rule stays for stocks/ETFs; crypto is fractional. Record as an amendment row (existing text untouched) and add the same note in `docs/trading.md`.
- **D-87 Crypto parameters (illustrative, labelled as such in docs and in `fee_schedules` notes):** a new immutable `fee_schedules` version for `CRYPTO` replaces migration 0025's placeholder: taker commission 10 bps (0.10 %), no minimum fee, base slippage 5 bps, size coefficient 0, collar from the spec (§6; if the spec gives none for crypto use 2 %), `model_version` `QBX-1/r8he` (same model). Fee rounding 8 dp HALF_EVEN as for stocks. No minimum notional unless the spec requires one. Crypto uses the 24/7 session already built in M7a (no `MARKET_CLOSED` for crypto while the feed is live; `STALE`/`UNAVAILABLE` still reject).
- **D-88 Tradability.** A forward-only migration sets `tradable_in` for the seeded crypto instruments so the engine accepts them (the M7a display-only rows). `INSTRUMENT_NOT_TRADABLE` still protects anything without it.
- **D-89 Preview gets a server-computed `maxQty`.** The preview response gains optional `maxQty` (decimal string): for BUY the largest quantity (rounded **down** to the instrument step) such that cash covers notional + fee at the estimated price; for SELL the position quantity. The browser must not compute it. The ticket may offer a "Max" button that fills this string. (Decided by the same pure function as the engine; a test proves `maxQty` fills and `maxQty + step` rejects.)

  - **B. SELL 0.001 (after A):** fill = 89,990.00 × 0.9995 = 89,945.005 → rounded **down** to tick = **89,945.00**; proceeds = **89.945**; fee = **0.089945**; consumed cost = round8(225.137525 × 0.001 / 0.0025) = **90.05501** (exactly 225.137525 × 0.4); realised = 89.945 − 90.05501 = **−0.11001**; ledger: `CASH +89.855055`, `FEES +0.089945`, `POSITION_COST −90.05501`, `REALIZED_PNL +0.11001` (sums to 0); cash after = **9,864.49239248**; remaining lot qty 0.0015, `cost_remaining` **135.082515**, avg cost 90,055.01.
  - **C. SELL the remaining 0.0015 (after B), same bid:** proceeds 0.0015 × 89,945.00 = **134.9175**; fee **0.1349175**; consumed cost = **135.082515** (lot fully consumed, by subtraction); realised = −**0.165015**; `CASH +134.7825825`; cash after = **9,999.27497498**; position closed, `POSITION_COST` = 0; total equity change −0.72502502 = fees 0.45000002 + realised loss 0.275025 (assert this identity).
  - **D. Proportional cost rounding and the by-subtraction rule (pure function test and one DB test on a made-up fractional instrument):** one lot qty 0.3 with `cost_remaining` 27.01; sell 0.1 → consumed round8(27.01 × 0.1 / 0.3) = **9.00333333**, remaining 18.00666667; sell 0.1 → consumed round8(18.00666667 × 0.1 / 0.2) = 9.003333335, an exact tie → HALF_EVEN → **9.00333334**, remaining **9.00333333**; sell 0.1 → lot fully consumed, consumed = **9.00333333** (by subtraction); total consumed = 27.01 exactly.

## 5. Out of scope

## 6. Common mistakes
Using JS numbers or `parseFloat` anywhere for quantity or money; rounding the per-unit cost and multiplying (accumulates drift) instead of using `cost_remaining` and the subtraction rule; consuming a lot partially with `round(qty × per_unit)`; forgetting HALF_EVEN on ties (vector D has one); posting `POSITION_COST` and lot cost from different formulas; letting `cost_remaining` change outside the engine function; fractional stock orders slipping through because only the UI blocks them; trusting a client `maxQty`; leaving `qty` CHECKs or casts that assume integers; weakening a test to get green; swallowing errors; editing old migrations.
