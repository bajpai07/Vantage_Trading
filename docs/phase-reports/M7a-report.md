- **Binance terms:** only the market-data-only FAQ was readable, https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md: "These URLs do not require any authentication (i.e. The API key is not necessary) and serve only public market data." It says nothing about permitted use. The Terms of Use page returned only navigation; the guessed API-terms and market-data-terms pages returned 404. **Terms not read.**
- **Coinbase terms:** the docs overview, https://docs.cdp.coinbase.com/exchange/docs/websocket-overview, says "Market Data APIs provide market data and are public." and that accessing it binds you to the Market Data Terms of Use. That document, https://www.coinbase.com/legal/market_data, returned HTTP 403. **Terms not read.** A browser-disguised fetch was not attempted because it would circumvent the block.
- Forum answers are not authoritative and were not used. **No conclusion on personal or portfolio-demo use is claimed.** A public launch needs written confirmation of the terms or a licensed provider behind the existing adapter interface.

## 9. Deviations and spec questions

1. **T2 skipped and live-adapter tests, fake server and `CRYPTO_FEED=live` removed** (founder's revision). The crypto mode is `CRYPTO_FEED=off|sim`; the stock mode stays `MARKET_DATA_SOURCE` (now `FIXTURE|SIM|PROVIDER`). Because the API has one provider per process, `CRYPTO_FEED=sim` requires `MARKET_DATA_SOURCE=SIM`. A mixed setup (for example fixture stocks and simulated crypto) is not possible; a future live crypto adapter would need a composite of providers.
2. **D-77 stricter than the prompt:** the prompt said FIXTURE and SIM require `DEMO_MODE=true` in staging and production; the existing D-48 forbids FIXTURE there outright and still does. SIM requires `DEMO_MODE=true`.
3. **Migration 0025 (CRYPTO fee schedule) was not in the prompt:** without it a crypto order was an HTTP 500 instead of `INSTRUMENT_NOT_TRADABLE` (found by the new test). Placeholder values, to be reviewed in M8.
4. **Feed contract extended, not versioned:** `FeedInfoResponse` keeps the four M6a fields and adds `demoMode` and `sources`; `InstrumentItem` gains `tradable`. The web client and its tests were updated.
5. **"Disconnected" for a deterministic feed** means "has not published recently" (a feed that stops is said so in a separate notice). In the e2e launcher the injected clock and the absence of a runner make that visible only when a test moves the clock.
6. **The overnight gap** is a fixed 14:30 UTC illustration, not DST-aware, and only in NYSE session mode.
7. **Search box placeholder** still says "Search stocks and ETFs" although crypto is searchable; not changed (copy is outside this phase's task list).
8. The e2e launcher now runs SIM in demo mode, so scripted `/quote` quotes in older e2e tests still carry the legacy `FIXTURE` label while the feed says SIM. That is test scaffolding only; the new spec uses the real SIM quotes via `/sim-refresh`.
9. The e2e suite regenerates earlier phases' screenshots when run; I restored them with git.

## 10. Known limitations and what M7b needs

- Prices are simulated: not real, and the demo says so everywhere. Volatility figures are a scale parameter, not calibrated; base prices are illustrative round numbers.
- The live crypto path is unverified (terms unread). Nothing is built for it beyond the provider interface and the `LIVE` mode value.
- Crypto is display-only: quantities are whole numbers in the ticket, the fee schedule is a placeholder, crypto trading is M8.
- No candles or prior close: the model can produce a price for any past second, so M7b can **generate candles from the same pure function** (history without storing ticks), and must decide whether SIM candles are computed on demand or persisted; day change and OHLC are still absent.
- E2E is local only, Chromium only, not in CI. The `ALWAYS_OPEN` banner text has no e2e (unit and integration only).
- `/v1/market/feed` status for SIM is based on the last publish time; a production runner outage is visible there and in the web notice, but there is no alerting.
- M7b needs: a candle contract and an endpoint, a decision on on-demand versus stored SIM history, and how prior close and day change are defined for a feed that never closes (crypto) or can run 24/7 (`ALWAYS_OPEN`).
