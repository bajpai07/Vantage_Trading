### 5.2 Failures, with root causes

**F1. `pnpm setup:env --port 56433` in the clone: "port 56433 on 127.0.0.1 is already in use. Nothing was written."** Root cause: the running developer database container `vantage-postgres-1` already publishes 56433. The driver continued and later steps failed for lack of an env file (`couldn't find env file: ...\.env.infra`); I killed the run and deleted the clone. Fix: port 56434. Related: `pnpm db:up` hard-codes the compose project `vantage`, which would collide with the running developer database, so the clone used `docker compose -p vantage-m10c ...` with the same file and variables instead. The acceptance command `pnpm db:up` was therefore **not run literally** in the clone (it is the same compose file).

**F2. First fresh-clone e2e: 2 failed, 162 passed (23.6 min).** `terminal.spec.ts:501` "keyboard only, from the search box to a filled order" (`register` timed out waiting for `/portfolio`; the test took 8.2 min against a 60 s timeout) and `ticket.spec.ts:269` "editing the quantity gives a new key..." (`review-button` stayed disabled; the test took 1.5 min against a 60 s timeout). **Root cause: the machine slept.** Windows System log: `10:23:57 The system is entering sleep (id 42)`, `10:23:58 resumed (id 107)`, `10:32:07 The system time has changed to 05:02:07Z from 04:53:58Z` (a jump of 8 min 9 s, id 1), and `10:34:09 entering sleep`, `10:34:13 resumed`, `10:35:14 The system time has changed to 05:05:14Z from 05:04:13Z` (1 min 1 s). Both durations match those jumps. The log shows no sleep or time change between 10:41 and 11:20. The whole e2e was then run again from scratch (section 5.1): 164 passed.

**F3. `pnpm compose:smoke` exited 13 in the clone, twice (and when run directly), with `Warning: Detected unsettled top-level await at ...compose-smoke.mjs:239`, before the teardown ran.** This was a **real defect in my script**, not the machine. With traces added I reproduced it: `fetch 0` was printed and nothing after, so the first request to the published web port right after `compose up` stayed pending while nothing else kept the Node event loop alive, so Node exited with code 13. It happened on some runs and not others (a direct run passed, the next failed). The exact reason the request stays pending is **UNVERIFIED**; the effect is proven. Fix (`b5c4034`): each attempt now has an abort timer (a normal, referenced timer), which keeps the loop alive and turns the hang into a retry. After the fix, two smoke runs in the clone passed. The failed runs left a stack up; I removed it with `down -v` and the final leftover check is empty.
