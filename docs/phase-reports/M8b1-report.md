Interpretations: `tif` is forbidden on MARKET and `referencePrice` is forbidden on LIMIT (strict objects); the validation message that says what is supported is appended by `ZodValidationPipe` (`CLEAR_VALIDATION_MESSAGES`); `released` appears on the cancel response only; a cancel that finds the order past its expiry commits the expiry (lazy, D-94) and answers 409 `ORDER_NOT_OPEN` (the 409 is not stored for replay, the expiry is committed); the snapshot `cash` column includes reserved cash (it is rebuilt from executions) and the equity identity is exact; DAY crypto expires at the next 00:00 UTC (illustrative, D-94); a refused fill (reserve shortfall) is unreachable by construction and has no executor test beyond the engine's refusal.

7. I did not object to any of D-91 to D-97.

## 10. Known limitations and what comes next

- **Machine reliability:** long runs here need the machine awake; I could not stop Windows suspending it (F1, F2, the 11.9-hour run). Treat a suspiciously long duration as a sleep.
- **Fill throughput:** one fill is one transaction (24 to 52 ms). 1,000 crossing orders on one instrument take 24 to 52 s to clear, longer than one matcher interval. Acceptable for a simulator; M8b-2's order book may want batching or a cheaper per-fill path.
- **No partial fills, STOP/STOP_LIMIT, IOC/FOK, modify, brackets** (out of scope). A later STOP/STOP_LIMIT phase can reuse the guarded transition (`triggered_at` is already writable), the matcher loop, `evaluateOpenOrders` and the reserve legs; it needs a trigger rule and, for STOP_LIMIT, a second reserve decision at trigger time, and it must keep the one-fill-per-order key `fill:{orderId}:1` or define a new one for partial fills.
- **M8b-2 (simulated order book and depth, UI)** needs from this phase: `limitFillPricing` is the single pricing function (a book would replace the slippage input, not the cap by the limit); `evaluateOpenOrders` is O(orders) per quote event; the matcher reads one quote per instrument per tick; the `orders_open_by_instrument` index and the open-orders listing already exist; the web ticket and open-orders list use only API strings, no browser arithmetic.
- **Typed-before-ready input:** under heavy load the quantity field can start empty after early typing (F5); the cause is unverified and only the test was changed. If real users can hit it, the ticket should read the field value on mount.
- **Idempotency key is memory-only** in the web client (as before): reloading during an uncertain order or cancel loses it.
